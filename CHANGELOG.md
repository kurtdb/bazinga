# Changelog

## Unreleased
- **Three more VS Code-extension-inspired tricks: Error Lens, a Todos panel, and a REST client.** (1) **Error Lens**: every diagnostic (language-server + quality-gate markers alike) now also renders inline at the end of its line, not only as a squiggly underline - on by default, toggle in Settings → Editor. Hooks the existing marker stream (`monaco.editor.onDidChangeMarkers`) rather than adding a second diagnostics pipeline. (2) **Todos**: a new bottom panel (next to Problems/Review) listing every `TODO`/`FIXME`/`HACK`/`XXX` comment project-wide, grouped by file, click-to-jump - a thin wrapper (`core/todos.js`) around the same ripgrep-first search engine the Search panel already uses (`core/search.js`), not a new file-walker. (3) **REST client**: a Thunder-Client-style HTTP request tab (command palette → "New HTTP request") - method/URL/headers (with autocomplete for common header names)/body, a response pane with status/time/headers/pretty-printed body, a "copy as curl" button, cancellable in-flight requests, and named requests saved to `.ide/requests.yaml` (git-shareable, same precedent as `.ide/scripts.yaml`). The request and response bodies are real Monaco models, not plain text areas - syntax highlighting and live JSON validation, language guessed from the `Content-Type` header (explicit) or sniffed from the body content (fallback), updated as either changes. Each request also has an **auth helper** (None/Basic/Bearer token/API key, header or query param) - a header-shorthand, not a real OAuth2 grant flow (no redirect listener, no token storage); **environment variables** via `.ide/environments.yaml` (hand-edited, same precedent as `.ide/scripts.yaml` - a named set of `{{var}}` values, one "active" at a time from a dropdown in the tab), substituted into the URL, headers, body and auth fields wherever `{{name}}` appears, with an unresolved token left literal rather than silently blanked; and saved requests can carry a **folder** tag that groups the sidebar list (no nested collections, no drag-and-drop - a folder is just a label some requests share). None of the three needed a new dependency - Monaco 0.57 already supports inline decoration content, and Node 23's global `fetch` covers the HTTP client.
- **Two more bundled "Recommended skills": `srs-draft` and `srs-review`**, ported from [Testany's SRS Writer](https://marketplace.visualstudio.com/items?itemName=Testany.srs-writer-plugin) ([source](https://github.com/Testany-io/srs-writer-plugin), Apache-2.0 - archived/read-only). `srs-draft` writes a Software Requirements Specification (`SRS.md`) section by section alongside a traceable, dictionary-keyed `requirements.yaml` (real entity-ID prefixes: `US-`/`UC-`/`FR-`/`NFR-`/`IFR-`/`DAR-`/`RISK-`/`ADC-`), asking before it ever fabricates a detail. `srs-review` runs a strict critical pass on any SRS - 3-layer method (surface scan, logic validation, critical analysis), 6 weighted dimensions (Completeness 25%, Clarity 20%, Feasibility 15%, Consistency 15%, Structure 15%, Business Value 10%) and a calibration note straight from upstream that most AI-written SRS should score 6-8/10, not 9-10 - and is meant to run as a fresh Agent-tool sub-agent when following straight after drafting, so the review isn't anchored by the drafting session's own assumptions. Deliberately dropped: upstream's 12-specialist content-generation fan-out and its bespoke tool-calling protocol, the VS Code chat/GitHub Copilot integration, and git/session/prototype-generation automation - none of that transfers to a plain skill folder, and two skills drafting/reviewing a shared schema cover the same ground without rebuilding an orchestration engine Bazinga doesn't have. The base rules and reviewer rubric were translated from the original Chinese; used the rules file's *real* 6-dimension weights rather than the marketplace listing's description of a 7th "AI Quality" dimension, which doesn't match the actual source (the listing's own specialist counts are self-admittedly inconsistent elsewhere too) - see `bundled-skills/srs-draft/NOTICE.md` and `bundled-skills/srs-review/NOTICE.md` for exactly what was ported, translated, or dropped.
- **The Fleet panel's expanded row now breaks a cloud agent's context total down into what it's made of.** Clicking a cloud-backed run (Claude API/similar) already showed a single session-total percentage and token count; there was no way to see how much of that was fresh input vs. served from the prompt cache vs. newly written to it vs. generated output - exactly the breakdown a user had been asking to see, inspired by a context-usage panel from another tool. Chose not to copy that panel's category-level split (Messages/MCP tools/Skills/System prompt/etc.) verbatim, since Bazinga has no data source for it - `fleet.js` parses only the four numeric fields Claude Code's own transcript exposes per message, with no per-category accounting. So the new line shows exactly those four measured numbers (`500 new in · 7k cache read · 1k cache write · 300 out`) rather than fabricating categories the underlying data can't support; `row.cloud` already carried all four through IPC unchanged, so this needed no new plumbing, just a renderer-side line.
- **The four agent-launch buttons (Claude/Copilot/Codex/Gemini) are no longer visually identical.** They shared one uncolored bot icon, distinguished only by label text, in an unbroken cluster with Terminal - the weakest-differentiated control group in an app whose whole pitch is running several agents at once. Each one's icon is now tinted by which CLI it actually launches (`agent-claude`/`agent-copilot`/`agent-codex`/`agent-gemini` classes on `.agent-btn`, matched from `a.command`), reusing the commit-graph lane colors (`--g1`/`--g3`/`--g5`) already defined in every theme rather than inventing new per-theme hex values; Claude keeps the existing plain accent color, since it's the one agent this app has its own health check and plan-limits integration for. A local-model or custom-command agent preset gets no class and falls through to the old uniform accent tint, unchanged.
- **Fix: the Changes/Agents rail badge's count text was below the 11px functional-text floor.** `impeccable detect` flagged `.rail button .badge` at `font-size: 9px` - the 14x14px circle it sat in was sized for a single digit and didn't leave room to grow. Now 11px text in an 18x16px pill (`border-radius: 8px`), still anchored to the button's top-right corner. The critique that found this also suggested reserving the badge's gold fill for counts that need action and using a neutral color for plain tallies (both badges here just count files/runs, not urgency) - left that part alone, since it's a direct reversal of an explicit earlier instruction in this project to keep the changes/agents notification gold on the default theme; flagging the tension here rather than silently picking a side.
- **Fix: the "Agent configuration" dialog showed a hook's raw shell command as if it were a description.** A hook titled "Stop" rendered its literal body - `[ ! -f '/Users/you/.claude/skills/impeccable/scripts/impeccable' ] || '...' hook` - inline, styled identically to every other item's prose description: unscannable, and it exposes your local absolute file paths in a dialog you might screen-share. The command was already kept separate from the description in `core/agentconfig.js` (the description there is just the hook's matcher, when it has one); the renderer was the one flattening both into the same line. Now the command sits behind a "view command"/"hide command" toggle, shown in a monospace block only once asked for.
- **Fix: several real WCAG contrast failures in the default Dark theme, below the 4.5:1 text floor.** Caught by `impeccable detect`, confirmed by computing actual contrast ratios rather than eyeballing it: (1) every input/textarea placeholder across the whole app relied on the browser's unthemed default gray, which measured ~3.9:1 against this app's dark backgrounds - never explicitly styled, in any of the 9 themes. Now themed via `input::placeholder, textarea::placeholder { color: var(--muted) }` (checked: `--muted` already clears 4.5:1 against `--bg` in every theme). (2) `--accent` text drawn directly on `--accent-bg` (the `.chip.on`/`.running`/`.armed`/`.accent` badges, the debugger's selected-frame highlight, and git ref/branch chips) measured 3.2:1 in Dark specifically - every other of the 9 themes already cleared 4.5:1+ on this same pairing, so only Dark needed a fix. Added a dedicated `--accent-on-bg` token (a lightened `#79b0ff`, 4.65:1) used by just those text colors, defaulting to the existing `--accent` value everywhere else so no other theme's colors change. (3) The quick-open palette's selected-row directory text (`.qo-row.sel .dir`) used `--muted` even when the row's background switched to `--accent-bg`, landing at 3.3:1; now uses `--fg` (7.36:1) when selected, matching how every other "selected row" treatment in the app already drops the muted/dim styling once highlighted.
- **The "Agent configuration" dialog no longer dumps everything open at once.** Claude Code's section (commonly 20+ items, since global skills/agents accumulate across every project on the machine) rendered fully expanded with full-paragraph, third-party SKILL.md descriptions - unscannable and unsearchable, right at the dialog whose whole job is auditing what these tools can do. Now: a runner's section opens by default only when it has project-scoped items (global-only runners start collapsed); each runner's global items live in their own nested, collapsed-by-default "Global" nested section instead of being dumped inline; every description over 140 characters collapses to one line with a "more"/"less" toggle instead of showing the full paragraph; and a filter input (by name, description or file) narrows the list live without re-scanning. The raw description text itself is left as-is rather than rewritten - it's content from the user's own third-party skill files, not this app's copy, and paraphrasing someone else's skill description risked misrepresenting it.
- **Fix: file/commit/stash/script names in the sidebar couldn't be selected or copied.** The shared `.row` class used by the Files tree, Changes panel, History (commits/stash/files) and Scripts list set `user-select: none`, so there was no way to drag-select a name and Cmd+C it - only right-click "Copy relative path" on the Files tree worked, and even that didn't cover History/Scripts. Now `user-select: text`, so normal click-drag-select-and-copy works everywhere that class is used. Also: Setup & health's "copy this command" button used `navigator.clipboard.writeText()` directly in a try/catch that silently swallowed failures instead of the `api.copy()` IPC path (backed by Electron's main-process `clipboard.writeText`, confirmed reliable) every other Copy button in the app already uses - switched it over for consistency.
- **Fix: the Changes/Agents rail badge count was unreadable, and unchecked rail labels were tiny.** The rail's unread-count badge (`Changes (13)`, `Agents (n)`) used accent-colored text on an accent-tinted background - on the active tab, whose own background is the same tint, the badge effectively disappeared (verified by pixel-sampling a real screenshot: zero accent-colored pixels rendered). It's now a solid gold (`--warn`) chip with dark text, readable in every state and theme; an empty badge (count 0) no longer renders a meaningless colored dot. The **Auto**/**Fix loop** toolbar checkboxes (and every other `label.check` checkbox) were plain unstyled native controls, which don't pick up the app's accent color at all under custom themes (Night/Nerd/Tron/WarGames); they're now custom-drawn to match the app's own control styling and theme tokens.
- **A live "Agent configuration" panel: MCP servers, skills, agents, hooks and instructions files, aggregated across every AI coding-agent runner found in the project** (Claude Code, Codex, GitHub Copilot, Gemini CLI) - **and now each runner's global, home-directory config too** (`~/.claude`, `~/.codex`, `~/.copilot`, `~/.gemini`), not just this project's own. Each runner's section splits into "This project" and "Global (~, every project on this machine)" only when both are present, so a project-only runner stays uncluttered; every item carries a `scope` so the two are never conflated - including with the Claude-only third case this deliberately leaves out, the personal-but-project-scoped record Claude Code keeps per project inside `~/.claude.json` (neither "this repo's config" nor "every project," so folding it into either would misrepresent it - see `NEXT_STEPS.md`). Shows a runner even when it has nothing configured ("No config detected") rather than hiding it; `AGENTS.md` shows once in a shared section since it's explicitly cross-tool here. Refreshes automatically on the same file-change signal the file tree already uses. Reads Codex's `.codex/config.toml` through a narrow hand-rolled TOML subset (no new dependency) and correctly treats Copilot's `.github/hooks/*.json` as a different shape from Claude's/Codex's shared hooks JSON shape, rather than assuming one format fits all three. The dialog itself also got a pass: it's wider, and every `<details>` section (here and in Setup & health) now has a proper header with a rotating disclosure arrow and spacing between sections, instead of bare unstyled `<summary>` text stacked edge to edge.
- **A read-only safety scan on fetched skills, before you ever see the install button - now also on `Update`.** `core/skillscan.js` scans every file of a `Fetch`/search-result skill candidate (never bundled/Recommended skills, which ship with the app) for hidden/invisible Unicode (zero-width characters, bidi text-direction overrides), download-and-execute shapes (`curl … | bash`, base64-decode-and-pipe, installing a package straight from a URL), destructive commands (`rm -rf /`, `chmod 777`) and prompt-injection-style phrasing ("ignore previous instructions", "do not tell the user", "exfiltrate"). Findings show as a badge and list right in the fetch preview, and the install confirmation repeats the count - pattern-matching, not a guarantee, same spirit as the existing secrets gate; nothing is blocked, you still decide. Clicking **Update** on an already-installed skill now runs the same scan against the new commit before replacing it (previously only the initial install was scanned - an update could silently bring in anything). Matching is also more robust now: text is normalized before matching (Latin-lookalike Cyrillic/Greek letters mapped back, zero-width characters stripped first) so a trigger word can't dodge the regex just by hiding a homoglyph or invisible character inside it, and one level of base64 is decoded and rescanned, so a payload meant to be read back later rather than executed directly still gets caught.
- **Six more bundled "Recommended skills":** `ub-mode` (Robert C. Martin's reduced "First Make it Work, Then Make it Right" principles, MIT, from [unclebob/ub-mode](https://github.com/unclebob/ub-mode)); `grill-with-docs`/`grilling`/`domain-modeling` (Matt Pocock's relentless-interview design-review skills, MIT, unmodified from [mattpocock/skills](https://github.com/mattpocock/skills) - install all three together, since `grill-with-docs` calls the other two by name); and the seven skills of Google's [Elephant-Goldfish Model](https://github.com/google/elephant-goldfish-model) (EGM, Apache-2.0) - draft a design spec with a deep-context agent, stress-test it with fresh zero-context reviewer subagents. EGM's skills assume a real plugin install (`${CLAUDE_PLUGIN_ROOT}`, a shared `docs/`/`agents/` folder); this bundled copy patches those into self-contained per-skill references instead. One real trade-off from that: reviewer isolation is instruction-level here, not the hard tool-restriction upstream's plugin registration gives it - see `NEXT_STEPS.md`.
- **Rename, "Go to symbol in workspace," AI inline completion, and a real step-through debugger.** Rename (`F2`/right-click) renames a symbol everywhere the language server finds it, applied as one workspace-wide edit. **Ctrl+T** fuzzy-searches every class/method/function across the whole project (tree-sitter, cached and kept fresh by the file watcher), not just the open file. Settings → Editor can turn on AI inline completion (ghost text as you type) backed by a local Ollama model via fill-in-the-middle, off by default. And a new **Run & Debug** panel adds a real debugger for Python: click the gutter to set a breakpoint, "Debug this file" (command palette or right-click) launches it via `debugpy.adapter`, and the panel shows the call stack and variables (expandable nested values) with Continue/Step over/Step in/Step out/Pause/Stop controls. Go/Rust/C#/etc. keep the existing Debug lens (wait for your own IDE to attach) - see `NEXT_STEPS.md` for the full list of scope limits this introduces.
- **Gradle quality gates and Gradle dependency/vulnerability insight.** Java projects built with Gradle now get the same treatment Maven projects already had: compile/test gates plus real PMD/Checkstyle/SpotBugs findings (reusing the existing report parsers - Gradle's XML schemas are byte-identical to Maven's), and "Dependency problems" now lists `build.gradle`/`.gradle.kts` dependencies and checks them against OSV.dev, instead of the static note it showed before. A Gradle task that doesn't exist yet (its plugin isn't applied) is reported as skipped, not failed; Checkstyle's missing-ruleset and SpotBugs's HTML-only-by-default report gap (Gradle's plugins differ from Maven's here) are both modeled as explicit prerequisites rather than silent false passes.
- **The "Clean Code" skill is installed on this project itself** (`.claude/skills/clean-code`, mirrored to `.agents/skills`), and the 21 warnings the new ESLint wiring found were cleaned up: dead unused vars/params removed, two `eslint-disable-next-line no-control-regex` comments added where the regex is deliberately matching control/ANSI characters (matching the existing convention elsewhere), and `no-unused-vars`'s `ignoreRestSiblings`/`argsIgnorePattern` options added to the config for the `const { drop, ...rest } = x` and `_e`-style-unused-callback-arg idioms already used throughout the codebase.
- **ESLint now actually runs on Bazinga's own code.** The built-in "ESLint" quality gate was permanently `skipped` here - no config, no local install - the same gap it flags for other projects. Added `eslint.config.js` (flat config, CommonJS, with the Node/browser global split the codebase's dual Electron-process/renderer-script split needs) and `eslint` as a devDependency.
- **Maven dependencies in "Dependency problems":** the Usage & insights panel's dependency check used to just note that Maven/Gradle needs a plugin Bazinga doesn't run. For Maven it now actually lists what's declared in `pom.xml` (`${property}` versions resolved, `dependencyManagement` excluded) and checks them against [OSV.dev](https://osv.dev)'s free, keyless vulnerability API - no local CVE database download the way the OWASP dependency-check plugin needs, so it fits the same "Check now" click npm audit and Dependabot already use.
- **PMD, Checkstyle and SpotBugs quality gates, ArchUnit tagging, and a bundled "Clean Code" skill.** Java projects now get real PMD/Checkstyle/SpotBugs findings (file, line, rule) alongside the existing Maven compile/test gates, scoped to files you actually changed so pre-existing issues across a touched module don't drown out the agent's own diff. ArchUnit needs no new gate - its JUnit-based architecture-rule failures already ran through "Maven test", and now get tagged `architecture-violation` instead of a generic test failure. Settings → Agent skills also gets a "Recommended skills" section bundled with the app (starting with *Clean Code*, a SOLID/Clean-Architecture review discipline) - install with one click, no git fetch required.
- **Fix: symbol lenses (usages/blame) could silently never appear for a file.** Monaco computes CodeLenses on its own schedule when a model is attached, with no retry of its own if that one attempt never happens (seen only under heavy system load); opening a file now also checks, once, whether anything got logged for it and nudges Monaco directly if not.
- **Adaptive guard rules, surfaced and extended:** the "you've overridden this N times, relax it?" suggestion (and a table of every override count, with a Reset) now also shows in Settings → Merge guard, not only in the merge dialog at the moment of an override. A second button, **Relax for this project**, writes the relaxed level into the project's own `.ide/config.json` instead of the IDE-level settings, for teams that commit their guard policy.
- **Session replay: inline diff preview.** Clicking a file under a commit step in the replay panel now shows a small side-by-side diff right there (a dialog-scoped Monaco diff editor), instead of requiring a click-through to a separate editor tab. An "open in the editor" link is still one click away for anyone who wants full editor features on it.
- **Auto-merge: an oversight tie-in, a Fleet indicator, and per-kind control.** "Autonomous" now defaults `autoMerge.enabled` on (still only once the guard is clean and the scorecard backs it; an explicit `enabled: false` still wins). The Fleet dashboard shows an "auto-merge armed" chip on any running agent whose project has auto-merge on for that kind of task. Settings → Auto-merge gets a checkbox per kind of task (tests/bugfix/refactor/feature/docs/review/other), so a project can auto-merge `docs`/`tests` but never `bugfix`, instead of one global on/off switch.
- **Semantic diff: cross-file renames, and fed into the AI review.** A function moved out of one file and pasted into another (same name or a new one) now shows as a single "moved"/"renamed" entry instead of a spurious remove-in-one-file-plus-add-in-another pair, in both the editor's symbol-changes button and the merge dialog's run-wide count. The AI review prompt (`reviewCommand`) now also gets a "Symbol changes" section ahead of the raw diff, so the reviewer model reads "renamed X → Y" instead of inferring it from a messy line diff.
- **"Run this test" and Debug for PHP, Ruby, Dart/Flutter, F# and Scala:** five more languages join Java/Kotlin, JS/TS, Python, Go, Rust and C# - chosen by cross-referencing which languages the editor already syntax-highlights out of the box against which had no tooling yet. PHPUnit, RSpec and Minitest, `dart test`/`flutter test`, and F#'s xUnit tests (riding the same `dotnet test` machinery C# uses) all get the full `Run test`/`Run all tests in this file`/*Debug* treatment - PHP via `XDEBUG_MODE=debug` (pauses only if an IDE is already listening on port 9003), Ruby via the `debug` gem's `rdbg --open --port=12345`, Dart/Flutter via `--pause-after-load` and a printed VM service URL, F# via the same `VSTEST_HOST_DEBUG=1` C# uses. Scala (ScalaTest FunSuite/MUnit's `test("name") { }` shape, via `sbt testOnly *Class -- -z "name"`) gets run-and-find but not debug - sbt's own debug flag targets its launcher JVM, not necessarily a project's forked test JVM, too inconsistent across projects to offer with confidence. RSpec's `file:line` selector is used directly (exact, not a name substring) since RSpec itself resolves it to whichever example or group starts on that line.
- **Debug a Go or C# test from the editor:** the *Debug* lens (next to *Run test*) now also covers Go and C#, alongside the existing pytest/JUnit/node:test support. Go runs under `dlv test --headless --listen=127.0.0.1:2345` (needs `dlv` installed separately - attach from VS Code's Go extension or GoLand as a remote config). C# sets `VSTEST_HOST_DEBUG=1`, so the test host prints its process id and waits for Visual Studio/Rider/VS Code to attach, the same flow those IDEs already support for `dotnet test`. Rust still has no lens - cargo has no equivalent "wait for a debugger" flag, so it stays "use your IDE's own debugger", same as Vitest/Jest.
- **Test coverage: the real built-in quality gates (not just a synthetic fixture) now run in the test suite.** The Go/Rust/.NET gates added below were only ever verified by a one-off manual script; `test/checks.test.js` now also runs every `DEFAULT_CHECKS` entry through a structural well-formedness check and runs the eight Go/Cargo/.NET gates end to end against a real fixture, so a typo in a gate's `match`/`pattern`/`parser` would fail the suite instead of shipping unnoticed.
- **Fix: the Go/Rust/C# "Run this test" lenses never actually rendered in the editor.** `registerTestLenses()` registered its CodeLens provider for Java/JS/TS/Python/Kotlin only - a second, separate list from the one the symbol-usages lens already used, which had Go/Rust/C# added. The command palette's `Run test at cursor` worked regardless (no language gate there); only the inline editor lenses were silently missing.
- **"Run this test" for Go, Rust and C#:** the `Run test`/`Run all tests in this file` lenses and the command palette equivalents now also know `go test`, `cargo test` and `dotnet test` (xUnit/NUnit/MSTest), on top of Maven/Gradle, Vitest/Jest/node:test and pytest. Go is scoped to its package, C# to its class; a Rust unit test (`#[test]` inlined in `src/`) only gets the single-test lens, since cargo has no "just this file" selector for that - an integration test file under `tests/` gets both. (Debug-lens support for Go and C# landed separately, below; Rust still has none - cargo has no "wait for a debugger" switch.)
- **Go, Rust and C# quality gates and language servers:** `go vet`/`go build`/`go test`, `cargo check`/`cargo clippy`/`cargo test` and `dotnet build`/`dotnet test` join the built-in gates (each skipped, not failed, when its tool is not installed - same as every other gate); Settings → Editor now also offers `gopls`, `rust-analyzer` and `csharp-ls` as one-click language server presets, alongside the existing jdtls/pyright/typescript-language-server ones. Symbol lenses, usages, duplicate-code and Semgrep already covered these three languages; this rounds out the automatic checks and editor intelligence to match.
- **Coding font picker:** Settings → General → Font switches the editor, every open terminal and every other monospace spot in the UI between Roboto Mono (default), JetBrains Mono, Fira Code, Cascadia Code, Source Code Pro and IBM Plex Mono — all OFL-1.1 and bundled, so it works offline and in the packaged app.
- **Auto-update checks by default:** `updates.check` is now on unless turned off (still never downloads or installs without a click, and still needs a real release feed - see docs). CI now also notarizes a signed macOS build automatically when `APPLE_ID`/`APPLE_APP_SPECIFIC_PASSWORD`/`APPLE_TEAM_ID` secrets are set alongside the existing certificate secrets, so an auto-update can actually install on macOS instead of just being signed.
- **Custom themes:** Settings → General → “Create custom theme…” takes three seed colours (background, text, accent) and derives the rest of the palette automatically, nudging every text colour until it clears the same 4.5:1 contrast bar the built-in themes are held to. An expandable section lets you override any generated colour by hand. Selectable right alongside the nine built-in themes.
- **Two new themes:** Tron (black, electric cyan on the Grid, amber where something needs to stand out, a faint grid-line texture) and WarGames (amber CRT phosphor, the WOPR terminal — "Shall we play a game?"). Both dark-only, same as Night and Nerd.
- **Safe-to-merge verdict:** the merge dialog shows one line — “Safe to merge”, “Needs a look” or “Blocked” — fusing the merge guard, the scorecard's track record for this agent and kind of task, and the auto-merge win-rate bar. Shown even when auto-merge itself is off, so you can see why a run would (or wouldn't) qualify before ever turning it on.
- **Auto-merge dry run:** a checkbox that logs what would have been auto-merged, and why, without actually merging — a way to build trust in the feature before switching it on for real.
- **Guard overrides, visible:** the scorecard screen lists how many times you've overridden each merge-guard blocker across every project, so the pattern behind “offers to relax it” (see Adaptive guard rules, below) is no longer a mystery.
- Semantic diff's symbol-change count now also appears in the merge dialog, summed across every changed file in the run, not just the one you happen to have open.
- Session replay no longer loses an agent's own commits the first time you open Review or Merge: they are snapshotted into the run's journal (shown as read-only history, since the per-file diff is genuinely gone once squashed into staged changes) before being folded away.

- **Semantic diff:** a “symbol changes” button in the diff toolbar summarises what actually moved — functions and classes added, removed, or renamed — instead of making you read it out of the raw line diff.
- **Auto-merge:** once the fix loop gets the gates fully clean, a run can merge itself without asking, but only for an agent and kind of task with a strong, proven track record in the scorecard (off by default; undo from the run list afterwards).
- **Session replay:** a scrubber over a run's own journal events and commits, so you can step back through what an agent actually did.
- **Adaptive guard rules:** override the same merge-guard blocker enough times and Bazinga offers to relax it, so recurring friction turns into a one-click settings change instead of repeating the same override forever.
- **Start-up safety net:** if the window cannot start (a script error, a crash, or no sign of life within 25 seconds) you get one clear message with “Reload”, “Copy details” and “Open log folder” instead of an empty window.

- **Undo a merged run:** adds a revert commit (history is never rewritten); refuses on uncommitted changes and leaves everything as it was if later changes clash.
- **Unattended workflow steps run in the Docker container** when it is set up (`containerWhenUnattended`: `auto` or `off`); otherwise a one-time tip.
